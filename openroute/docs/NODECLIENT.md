# 节点客户端

仓库的 `cmd/nodeclient` 是与本面板 HTTP 协议配套的节点程序。
面板程序本身以及其它项目的节点二进制都不能代替它。

内网、IPLC / IEPL、多网卡、`--connect-host`、本地 / NAT 端口参数及完整示例见
[专线配置指南](PRIVATE_LINES.md)。`nc20260922.2` 起这些本地网络参数已接通注册、心跳及对端配置下发。

## 构建和下载

在仓库根目录运行 `./deploy/build.ps1`（PowerShell），构建面板与 Linux
amd64、amd64v3、arm64 三种节点。将 `deploy/node-binaries/` 随面板一起部署到
面板工作目录下的 `node-binaries/`，或通过面板配置 `node-binary-path` 指定目录。

每个架构目录包含 `rel_nodeclient` 和 `version.txt`；后者须与程序 `-version`
输出一致，`build.ps1` 会一起生成。下载响应提供版本与 SHA-256 元数据供升级校验。
`amd64v3` 需要支持 x86-64-v3 的 CPU，普通 `amd64` 使用兼容性更广的 v1 指令集。

文件布局为 `node-binaries/<arch>/rel_nodeclient`，下载地址为
`/api/node/binary/<arch>`。如需固定版本，额外放置
`node-binaries/<version>/<arch>/rel_nodeclient`，再传 `?version=<version>`。
缺失文件会返回明确的 404；不支持的架构或非法版本参数返回 400。

Linux 下也可直接构建：

```bash
cd openroute
mkdir -p node-binaries/amd64
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 GOAMD64=v1 \
  go build -trimpath -ldflags '-X main.version=nc20260922.2' \
  -o node-binaries/amd64/rel_nodeclient ./cmd/nodeclient
printf '%s' nc20260922.2 > node-binaries/amd64/version.txt
```

## 安装与运行

安装脚本面向 Debian 11+、Ubuntu 22.04+，需要 root 权限和 systemd。
所有参与新功能的入口、出口、链式中继和反向节点都需要更新至 `nc20260922.2`。
`nc20260922.1` 已支持面板远程升级；更早且尚未实现升级任务的客户端，需要在对应
服务器重新执行面板生成的安装命令。要同时持久化新的网络参数，也可以直接重跑
安装命令并追加参数。先更新面板和下载文件，再更新节点；更新面板不会自动替换
远端正在运行的节点程序。设置 `DISABLE_EXECUTE=1` 的节点需本机手动更新。

在面板创建节点后，复制该节点的安装命令到目标服务器执行。
公开 `/install.sh` 只包含通用脚本，不会查询或内嵌现有节点密钥。
`-u`、`-t` 参数由目标机上的脚本解析。默认安装目录为
`/opt/openroute-node`，服务为 `openroute-node`，与面板目录隔离。

客户端注册后定期发送心跳、拉取配置并报告应用结果。已下载的配置保存在
节点目录，面板暂时不可达时可以恢复本地配置；配置与密钥属于敏感文件。

```bash
systemctl status openroute-node
journalctl -u openroute-node -n 50 --no-pager
/opt/openroute-node/rel_nodeclient -version
/opt/openroute-node/rel_nodeclient -c /opt/openroute-node/config.yml -check
```

## 转发能力与条件

| 能力 | 当前行为与条件 |
|---|---|
| 单端转发 | TCP、UDP 直接连接目标，支持单端口及端口段 |
| 双端隧道 | 入口与出口协作，TCP 支持 `direct`、`ws`、`http`、`tls` 四种外壳 |
| 双端 UDP | 支持原生 UDP 隧道；启用 `udp_over_tcp` 后通过所选 TCP 外壳传输 UoT（UDP over TCP） |
| 反向隧道 | 出口主动连接入口，支持上述四种外壳；反向 UDP 使用 UoT |
| 链式出口 | `chain_groups` 是完整的 2～3 跳出口路径，最后一跳直接连接目标，不再追加普通出口组 |
| SNI 分流 | 根据 TLS ClientHello 的 SNI 选择主规则的子规则，按实际选中的规则连接及计量 |
| 负载均衡和故障转移 | 支持配置的目标与出口节点选择策略、健康探测及普通出口组的故障转移 |

链式仅支持 TCP，入口设备组必须设置 `disable_udp`；链中的出口组不能配置故障
转移组，链式也不能与反向模式组合。普通双端和反向场景仍可使用其支持的 UDP/UoT。

这里的 `ws` 按仓库规格书 §4.5 实现 **HTTP 握手伪装，不是 RFC 6455 WebSocket
帧协议**。握手后承载本项目的隧道数据，不能直接用通用 WebSocket 客户端或要求
标准帧的代理替代节点。`http` 也是隧道外壳，不是通用 HTTP 正向代理。节点控制
连接和 WebSSH 的 WebSocket 属于另一条通道。

TLS 隧道使用面板保存的节点证书及对端证书 pin，每个节点只收到自己的私钥。
TLS 入站解密策略需要对应规则的证书与私钥。HTTP 路径、协议和 SNI 策略按可识别
的握手内容执行；检查加密后的 HTTP 路径需要先终止 TLS。

原生 UDP 使用 AES-GCM 认证加密及序列号防重放，每包封装开销 **66 字节**，
最大有效载荷 **65,400 字节**。这是程序上限，实际数据报还受路径 MTU 限制，
不保证这么大的包能无分片传输。

未实现 `NYA_PROXY` 外部 SS、TUIC 等代理接入。设置该环境变量会导致相关配置
校验失败，不能把其它项目的代理兼容选项视为本客户端已实现的能力。

## 默认端口和连通方向

面板 `nodePorts` 在端口字段为 0 时采用以下默认值，节点管理中可以修改：

| 端口 | 协议 | 用途 |
|---|---|---|
| 28080 | TCP | direct 节点隧道 |
| 28081 | TCP | ws / http 握手伪装隧道 |
| 28082 | TCP | TLS 节点隧道 |
| 28083 | UDP | 原生 UDP 隧道 |
| 28084 | TCP | 反向连接入口，外壳由规则决定 |

普通隧道要求入口能够连接出口的相应端口，链式要求相邻各跳连通，反向要求出口
能够连接入口的反向端口。规则可单独指定 `reverse_port`。客户端访问的规则监听
端口也需在入口放行；节点连接地址和实际监听地址应与网络环境一致。

## 用户限制与配额

用户速率、连接数、IP 数和流量额度为 0 时继承用户组配置；组也为 0 表示不限。
设备数限制按用户配置。规则与用户限制叠加，同一入口的多条规则共享用户用量。
用户禁用、过期及额度耗尽状态通过配置下发到节点。

**速率限制只作用于 TCP，UDP 不做限速整形。** TCP 同时受规则和用户速率约束；
UDP 仍参与会话限制、流量计量和用户额度检查。

速率、连接、IP、设备限制在**每个入口独立执行**，不是跨入口的全局计数。
设备通过 TLS/HTTP 特征等指纹近似识别，不能与真实物理设备保证一一对应；无法
识别时退回来源 IP。多入口共享配额依赖面板汇总与下发，上报间隔及网络延迟可能
造成超额，并非全局原子的严格额度分配。

面板暂时不可达时，节点继续运行最后有效的缓存配置；新的规则、禁用和用户策略
变更，以及其它节点新增用量不能即时同步到断连节点。

## 配置同步、计量与告警

节点通过控制长连接接收更新提示，保留 HTTP 轮询兜底；版本号与实际运行配置的
hash 一起参与漂移检查。完整配置先校验再应用，应用失败会报告错误并保留、恢复
上一份有效配置；若监听恢复失败，也会报告恢复错误。面板按所有相关节点的确认
汇总规则状态，旧版本或与下发内容不符的 ACK 不会把新配置标为成功。

流量按规则、节点、方向、**实际配置版本及 UTC 小时**采样，记录真实字节和乘以
方向倍率后的计费字节，链路各出口段也计入出口倍率。面板保存下发时的用户归属
和倍率，延迟报告不会因之后转移规则或修改倍率而改扣新用户。

待报流量和固定批次持久化后可跨重启重试；面板在同一事务中保存批次收据和统计，
收到匹配确认后节点才清除批次，避免重复扣费。跨小时、跨月积压按原采样时间归档。
尚未采样落盘的内存增量不具备断电恢复保证。

告警覆盖节点离线、CPU/内存/磁盘、同步失败、用户/规则/节点流量百分比及证书
到期，支持 webhook、Telegram、邮件、持续时长、静默期及恢复通知。用户流量
百分比采用有效额度；规则和节点告警需独立配置累计计费流量基准，该基准只告警、
不限制转发，已有基准为 0 的告警需补填。证书告警检查面板及规则配置的 TLS 证书。

## WebSSH、任务与在线升级

Linux 节点支持真实 PTY WebSSH、命令执行和重启；任务记录持久化并按 ID 去重，
终端会话隔离，断开时清理对应会话。操作使用节点服务账户权限，默认安装为 root。

新客户端在线升级要求 HTTPS 面板地址、版本及 SHA-256 元数据、架构匹配的 Linux
ELF，以及 systemd / `systemd-run`。替换前检查版本和配置并保留旧二进制，独立
systemd watchdog 等待新程序启动且向面板注册确认；120 秒内未确认时恢复旧程序
并重启节点服务。安装脚本设置 `OPENROUTE_SYSTEMD_UNIT`，自定义部署也需提供
可识别的服务单元。

环境变量 `DISABLE_EXECUTE=1`（也接受 `true`、`yes`），或节点 `config.yml` 中的
`disable-execute: true`，会禁止 WebSSH、远程命令、远程重启及远程升级，转发和
配置同步仍可运行。修改后在节点本机重启服务，面板会显示节点上报的执行禁用状态。
